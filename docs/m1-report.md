## 过程中发现的问题

1. **forward 的参数与返回顺序曾依赖 JSON 键顺序。** 为了让 `.loom` 用排序后的键（git 友好），IR 升级到 0.2，增加显式的 `interface`；0.1 文件打开时自动迁移。
2. **torch.fx 会把某些函数的默认参数显式记录下来**（`F.softmax` 多出 `_stacklevel=3, dtype=None`）。导入器现在忽略与函数默认值相同的多余关键字参数。
3. **Vite 在移动源文件后会保留过期的模块图**，页面白屏，重启开发服务器即可；M0 也遇到过类似情况，暂未影响构建与测试。
4. **测试关闭仍有未保存更改的窗口时会被“是否保存”对话框挡住**，说明关闭保护有效；冒烟测试改为直接销毁窗口。

## 已知限制

- 仍然只支持扁平图：自定义子模块会被展平，`x.view(x.size(0), -1)` 这类依赖运行时值的参数、张量切片 `x[:, 0]` 都会被拒绝并给出原因。
- 导入后，函数式算子的变量名会变成 torch.fx 的命名（`relu`、`cat_1`），层的名字保留。
- 部分算子（如 LSTM）在 meta 设备上无法推形状，会退回 CPU 用真实张量跑一次；超大模型时会占内存。
- “一键创建环境”只验证了命令方案，没有在本机真实执行（需下载约 200 MB）。
- Vite 提示：将来默认的原生配置加载器要求 import 写文件扩展名，届时需要调整 `vite.config.ts` 的导入。

## 对 M2 的建议

1. 层级与模块化（F4.1–F4.4）：模块定义、下钻、复用、重复块；导入时保留用户子模块，同时解决 `state_dict` 键名问题。
2. LibCST 静态导入（F6.1）：找回变量名与超参数表达式，并与 fx 结果合并。
3. 代码块降级（F6.3）：不支持的片段保留为代码块节点，而不是整体失败。
4. 补齐 M1 尾项：中英文切换、对齐 / 分布、网格吸附开关。
5. 推送仓库后先跑一次 CI，确认三平台都通过。
