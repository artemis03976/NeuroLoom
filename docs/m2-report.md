# M2 报告：层级与静态导入

2026-10-23 · 分支 `m2/modules-and-import`（基于 `main`）

**结论：M1 报告建议的五件事都已完成，PRD 中 M2 的功能（F4.1–F4.4、F6.1、F6.3）也已就位。**

- 模型现在可以分层：
  - 选中节点按 Ctrl+G 打包为模块，双击进入。
  - 同一模块可以多处复用，每个实例传入不同的超参数。
  - 模块可以串联重复 ×N。
- 从代码导入默认改为静态解析，完全不执行代码。子模块、变量名、超参数表达式和 `nn.ModuleList` 循环都会保留。
- 解析不了的语句保留为代码块，解析不了的类保留为源码，因此导入不会整体失败。
- 界面和诊断信息都有中文和英文。

有一处与 PRD 不同：静态解析用标准库 `ast`，没有用 LibCST，原因见“与 PRD 的偏差”。

### 静态导入

导入时不执行用户代码，torch 只用来读取层构造函数的签名。按语句处理：

| 位置 | 能结构化的 | 其余 |
| --- | --- | --- |
| `__init__` 的参数 | 变为超参数，保留类型注解和默认值 | 带 `*args` / `**kwargs` 时整个类保留为源码 |
| `self.x = nn.Conv2d(...)` 等 | 变为层节点；引用构造参数、局部变量或文件级常量的实参保留为表达式 | 参数不受支持时，该语句放到 `__init__` 末尾原样保留 |
| `self.x = Block(...)` | 变为模块实例 | — |
| `nn.Sequential(...)` | 变为内联序列容器，可以进入查看 | — |
| `nn.ModuleList([X(...) for _ in range(n)])`，以及首份不同的写法 | 变为重复块 | 其他写法放到 `__init__` 末尾 |
| 第三方模块（`timm.layers.DropPath(...)`） | 变为外部模块节点，构造参数原样保留 | — |
| `self.scale = d ** -0.5` | 变为模块常量 | — |
| 权重初始化、`register_buffer` 等 | — | 原样追加到 `__init__` 末尾 |
| `forward` 里的层调用、算子、运算符、元组解包、`+=`、`for blk in self.blocks: x = blk(x)` | 变为节点和边 | 其余语句（`x.view(x.size(0), -1)`、切片、共享权重的第二次调用……）变为代码块 |
| 其他方法、类属性 | — | 原样保留 |
| 文件头的 import、常量和辅助函数 | — | 原样保留为“文件头代码” |

导入完成后，对话框会逐个类报告导入级别（L1 / L1+L3 / L3），并说明降级的原因。

### 运行一次，补全形状

代码块和外部模块里的计算，形状推断看不到，下游节点因此没有形状。“运行一次，补全形状”是 M1 报告里“与 fx 结果合并”的落地方式，流程如下：

1. 编辑器生成插桩代码，在每个代码块和外部模块之后记录张量形状。
2. 后端在子进程中运行两次模型。两次运行中，每个符号维度（B、T……）取不同的值。
3. 两次相同的维度是常数，不同的维度按符号乘积推回，例如 `B`、`B*T`、`B*4`。
4. 推回的形状写成这些节点的声明形状。

导入报告页和模型面板中都有这个按钮。

  - `kind: 'module' | 'code'`

- `LoomProject`：`preamble`

## 过程中发现的问题

1. **zustand 选择器返回新数组会导致无限重渲染。** 检查器里一个 `diagnostics.filter(...)` 写在了选择器内，选中节点时页面白屏。已改为先取原数组再过滤，并检查了其余选择器。
2. **Vite 开发服务器又一次提供了过期的编译结果。** 一个文件在两次编辑之间被编译成中间状态，之后没有重新编译，页面报“未定义”而白屏，重启开发服务器后恢复。M0、M1 都遇到过这个问题；按 Vite 的提示，后续可以给配置和 backend-bridge 的 import 加上扩展名。
3. **`nn.LSTM`、`nn.GRU`、`nn.RNN` 的构造签名是 `(*args, **kwargs)`**，读不出位置参数的顺序。导入器遇到这种签名时，改用节点规格中的参数顺序（与 PyTorch 文档一致）。
4. **表达式作为运算符的右操作数时，需要按优先级加括号**：`x - (a - b)` 不能写成 `x - a - b`。代码生成现在会检查优先级。
5. **模块递归引用自身时，如果端口未连接，原来先报“未连接”，递归不会被报出。** 现在先检查递归。

## 与 PRD 的偏差

| 项 | PRD | 实际 | 原因 |
| --- | --- | --- | --- |
| 静态解析实现 | LibCST | 标准库 `ast` | 不增加依赖，用户已有的环境直接可用。<br>代码块和保留源码按原文截取，注释和格式不会丢失。<br>LibCST 的价值在“最小改写回写源码”（P1，PRD 11.5），等做到那一项时再引入 |
| 与 fx 结果合并 | 按限定名对齐追踪结果 | “运行一次，补全形状” | 静态解析已经保留了结构、变量名和表达式，执行代码真正补上的只有看不到的形状。<br>torch.fx 追踪仍可作为另一种导入方式使用，但依然会展平层级；保留层级的动态导入属于 M3 的 F6.2 |
| 重复块的导出 | 参数一致时可选 `nn.Sequential` | 一律 `nn.ModuleList` + `for` | 导出选项属于 F5.3（M3）。`nn.Sequential(*[...])` 写法可以正常导入，键名相同 |
| 重复对象 | 模块实例 | 模块实例和单个层 | `nn.ModuleList([nn.Linear(...) for _ in range(n)])` 很常见 |
| 内置复合模块（9.6） | ResidualBlock 等可展开的模板 | 未做 | 现在可以先导入一段代码作为模块；内置模板放到 M3 补齐模板时一起做 |

## 已知限制

- `forward` 带默认参数（如 `mask=None`）或 `*args` 的类，会整体保留为源码。
- 同一个层在 `forward` 中被调用两次（共享权重）时，第二次调用变为代码块。
- 异构的 `nn.ModuleList`、`nn.ModuleDict`、在循环里 `append` 构造的层，会放到 `__init__` 末尾原样保留；`forward` 中用到它们的语句变为代码块。
- 代码块和外部模块的声明形状只保存在 `.loom` 中，不写进导出代码；重新导入导出的代码后，需要再运行一次补全形状。
- 一个模块被多个实例使用时，代码块的声明形状只有一份。如果不同实例的形状不同，下游的推断会以声明值为准。
- 代码块之间如果有不在代码里的数据依赖（只靠语句顺序），自动布局后的语句顺序可能改变。
- 动态追踪仍会展平层级（M3 的 F6.2）。
- 主包超过 500 KB，Vite 会给出提示，暂不处理。

## 对 M3 的建议

1. 动态导入（F6.2）：追踪时保留用户模块，按限定名与静态解析结果对齐，覆盖 `_make_layer` 这类需要运行才能确定结构的写法。
2. 补齐内置复合模块（9.6）与剩余 8 个模板，模板优先用模块和重复块组织。
3. 导出选项（F5.3）：重复块导出为 `nn.Sequential`、形状注释、自测片段。
4. 给 Vite 配置和 backend-bridge 的 import 加上文件扩展名，避免开发服务器提供过期的编译结果。
5. 收集 20 个以上真实仓库的模型文件作为导入语料库，统计 L1 / L3 的比例，按频率扩展静态解析。
