### 动态导入

先做一次静态解析，再在子进程中实例化模型并运行两次（两组符号取值）。之后逐个类按以下顺序取结果，保证结果不会比静态解析差：

1. **静态解析完全结构化（L1）的类**：保留静态结果，包括变量名、超参数和表达式。
2. **其余的类**：用 torch.fx 追踪，每个子模块作为一个叶子，得到一层的结构（L2）。
   - 一个类在模型中有几种实际结构，就产生几个定义，如 `BasicBlock`、`BasicBlock2`。
   - 表达式变成具体数值，这正是 PRD 对 L2 的描述。
   - `nn.Sequential` 变成序列容器。
   - 首尾相接调用的 `nn.ModuleList`：各份相同时变成重复块；不同时变成序列容器。
   - 第三方模块：构造参数是常量时保留为外部模块，否则一并追踪。
3. **追踪失败的类**：退回静态结果，其中的子模块仍按上面的规则逐个处理。原样保留的代码（`__init__` 尾部、源码类）用到的类，会以原类名和原签名保留静态定义。
4. **整个模型无法运行时**：返回静态结果，并附带说明。

导入一个按 ResNet-152 配置（[3, 8, 36, 3] 个 Bottleneck，输入 224×224）的模型：
- 静态导入 1.4 秒，动态导入 2.7 秒，PRD 的上限分别是 3 秒和 10 秒。
- 动态结果有 17 个模块定义、186 个节点，没有代码块。

- 生成的代码能以 `strict=True` 加载原模型权重，并且输出相同；
- 再次导入生成的代码，得到的代码不变。

**动态模式的明显收益**：`_make_layer` 和循环构造的类（ResNet、MobileNetV2）从 L3 / L1+L3 变成没有代码块的 L2。

**动态模式剩下的代码块**：主要来自 `x.shape` / `x.size()`、张量下标，以及节点库还没有的函数（`F.adaptive_avg_pool2d`、`torch.exp`）。补上这些算子是提高覆盖率最直接的办法。

### 模型分析（F8.2）

底部面板新增“分析”页：
- 列出参数量（及 float32 下的内存）、FLOPs（及 MACs）、激活内存和显存估算（参数加激活）。
- 按 `named_modules()` 的命名展开实例树（如 `layer1.0.conv1`），可以按任意一列排序，点击一行就跳到对应模块并选中节点。
- 符号维度（B、T……）的取值可以修改，默认 B = 1，其他为 128。
- 遇到代码块、外部模块或未知形状时，相关的值标为“≥”或“?”。

FLOPs 的计算口径：
- 与 `torch.utils.flop_counter.FlopCounterMode` 一致：一次乘加计 2，只有矩阵乘、卷积和注意力计入。
- 在前端按 NodeSpec 公式计算，不需要 Python。
- 循环层（RNN / GRU / LSTM）按输入投影和逐步的隐状态投影计入。PyTorch 在 x86 上把 LSTM 作为融合的 oneDNN 算子执行，FlopCounterMode 看不到，计为 0；在 ARM（macOS）上则按矩阵乘计入。编辑器按实际计算量计入，测试中关闭 oneDNN 后与 PyTorch 比对，各平台结果一致。
- 验证：
  - 每个带公式的节点和 12 个变体，与 FlopCounterMode 逐个比对一致；
  - 整个模型（ResNet、首份不同的重复层）的 FLOPs 和参数量与 PyTorch 相等；
  - 12 个模板和 7 个复合模块：没有代码块的，FLOPs 与 FlopCounterMode 完全相等；有代码块的（VAE、ViT、GPT-2），编辑器给出的值是下界。

### 大图性能

**编辑**：
- 每个节点要显示的内容（“face”）在每次修改后统一算一次，没有变化的节点沿用原对象，因此不会重绘。
- React Flow 的节点、边对象只在位置、选中状态或标签变化时才重建。
- 代码预览按行缓存，修改只重绘变化的行。

**画布**：
- 视图超过 250 个节点、且布局完成后，只渲染视口内的元素（React Flow 不测量没渲染的节点，所以要等布局完成）。
- 缩放低于 40% 时节点简化为色块加名称：只用 CSS，节点尺寸不变，不需要重新测量。
- 边的动画按 PRD 8.2 降级：可见边不超过 300 条时用粒子；超过 300 条或缩放低于 40% 时用虚线；超过 600 条、缩放低于 25% 或系统开启“减少动态效果”时静止。
- 选中一个节点时，只有它的上下游路径在流动。
- 平移、缩放手势进行中，整张图作为一个合成层移动，动画暂停。
  - 加这一项之前，全图可见时每帧都要重绘全部节点和边，测得约 20 fps（当时用程序逐帧设置视口来测）。
  - 加上之后用鼠标拖动来测，见下表。

`npm run perf` 启动生产构建的桌面版，在真实窗口中测量。为了不受显示器刷新率和锁屏影响，测量时不按刷新率限制帧数，测得的是“能画多快”。平移是把图居中后用鼠标来回拖动。下表是多次运行的范围：

## 过程中发现的问题

1. **动态导入**：
   - 为原样代码补回类定义的循环，因内容去重返回了刚被改名的定义，会一直循环下去，表现为语料测试卡住。已改为每个类名只处理一次。
   - 记录构造参数时临时替换了 `nn.Module.__new__`。CPython 中删除类上的 `__new__` 并不能恢复原状，之后同一进程里构建任何模型都会报 `object.__new__() takes exactly one argument`。桌面后端是常驻进程，动态导入之后“运行一次补全形状”就会失败。已改为钩子常驻、按开关记录。
2. **语料测试原来每个用例启动三次 Python**，用时 83 秒，而且 Python 端的报错被吞掉了，只显示“JSON 解析失败”。改成全部用例共用三个进程后用时 7 秒，并能看到报错的 traceback。由此发现了三个静态导入问题：
   - 同一个 `__init__` 局部变量被重新赋值时，只记住了最后一次赋值；
   - 条件赋值（`if ...: identity = f(x)`）形成的代码块，没有把变量的旧值作为输入；
   - 辅助方法调用的重复块被写成了 `nn.ModuleList`，无法调用。
3. **编辑器**：
   - zustand 选择器返回新对象（`?? {}`）导致无限渲染、页面空白，M2 也遇到过。
   - 每次修改都重建全部 React Flow 节点对象，1000 个节点全部重绘。已改为沿用未变化的对象。
4. **类继承**：只写 `__init__`、继承父类 `forward` 的配置子类，原先没有输入端口；现在端口取自父类的 `forward`。

## 与 PRD 的偏差

| 项 | PRD | 实际 | 原因 |
| --- | --- | --- | --- |
| FLOPs 的计算位置 | 后端用 FlopCounterMode 按模块统计 | 前端按 NodeSpec 公式计算，口径与 FlopCounterMode 相同 | 不需要 Python，改参数后立即更新；与 FlopCounterMode 的一致性由测试保证。<br>代价是代码块内部的计算不计入，此时显示为下界 |
| 动态导入的 L2 定义 | — | 同一个类的每种实际结构各是一个定义（`BasicBlock2`……），表达式是具体数值 | 符合 PRD 对 L2 的描述。把结构相同的定义合并、并找回超参数，是下一步的改进 |
| 边动画降级 | 虚线或静止 | 600 条可见边或 25% 缩放以内用虚线，超过后静止；平移时暂停 | 实测虚线动画在全图可见时会让帧率降到 20 fps |

## 已知限制

- **PRD 成功指标还没测量**：
  - “torchvision 分类模型动态导入 ≥ 90% 无代码块”需要在测试环境装 torchvision。追踪逻辑已经支持构造参数里带类的第三方模块（如 torchvision 的 `ResNet(Bottleneck, …)`）。
  - “开源模型文件静态导入成功率 ≥ 80%”需要 50 个文件的语料库，现在只有 10 个。
  - 可用性测试还没有做。
- **模板**：
  - ViT 的 class token 和位置编码是 `nn.Parameter`，导入后是常量，不计入参数量（少 38,016 个）。
  - 代码块的声明形状不随超参数变化（M2 已知）。
- **动态导入**：同一类的多个结构是多个定义，修改其中一个不影响其他。
- **布局**：ResNet-18 模板 `layer2` 中自动布局有节点部分重叠，导出的图片会如实画出重叠。
- **性能**：
  - `npm run perf` 的数值取决于机器，每次运行也有波动；开发模式下的修改延迟比生产构建高 2–3 倍。
  - 全图可见（缩放 0.1）时的平移只有 57–64 fps，余量不大。
  - 低缩放下如果把整张图拖出视口再拖回来，React Flow 的视口裁剪会反复卸载、重建节点，帧率会降到 25 fps 左右。

## 对下一阶段（v1.0 发布）的建议

1. **跑一次发布工作流**：推送一个测试标签（如 `v0.3.0-rc.1`），在 macOS 和 Linux 上实际构建并跑打包冒烟测试；配好签名证书后验证签名和公证。
2. **测量 PRD 成功指标**：
   - 在 CI 的测试环境装 torchvision，对分类模型做批量动态导入，统计无代码块的比例；
   - 语料库扩充到 50 个文件，统计静态导入成功率。
3. **按语料统计补节点库**：先补 `F.adaptive_avg_pool2d`、`F.max_pool2d`、`torch.exp`、张量下标，再把结构相同的 L2 定义合并并找回超参数。
4. **v1.x 功能**：注释便签与分组（F1.7）、边的粗细 / 颜色编码（F3.6）、原地展开（F4.5）、ONNX 导出（F5.4）、按名称从模型库导入（F6.4）、自定义节点（F9.1）。
